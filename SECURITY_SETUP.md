# 🛡️ Настройка системы безопасности

Этот файл содержит инструкции по настройке системы безопасности для админ-панели.

## ✅ Что было добавлено

### 1. Rate Limiting (Ограничение попыток входа)
- Максимум **5 попыток** входа за **15 минут**
- Автоматическая блокировка IP на **30 минут** при превышении лимита
- In-memory хранилище (перезапускается при рестарте сервера)

### 2. Логирование всех попыток входа
- Консольное логирование (попадает в логи сервера)
- Опциональное сохранение в Supabase
- Отслеживание IP, user-agent, статуса и причины

### 3. Мониторинг безопасности
- Новая страница `/admin/security` с:
  - Статистикой попыток входа
  - Таблицей последних попыток
  - Информацией о настройках защиты

### 4. Улучшенный UX
- Показ оставшихся попыток входа
- Сообщение о блокировке с временем разблокировки
- Блокировка кнопки входа при превышении лимита

## 📋 Инструкция по настройке

### Шаг 1: Создать таблицу в Supabase

1. Откройте ваш проект в [Supabase Dashboard](https://app.supabase.com)
2. Перейдите в **SQL Editor**
3. Создайте новый запрос и вставьте содержимое файла:
   ```
   supabase/migrations/create_admin_login_attempts.sql
   ```
4. Нажмите **Run** для выполнения

### Шаг 2: Проверить настройки окружения

Убедитесь, что в `.env.local` есть:

```env
# Admin credentials
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ваш_надёжный_пароль

# Supabase (уже должно быть)
NEXT_PUBLIC_SUPABASE_URL=your_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=your_key
SUPABASE_SERVICE_ROLE_KEY=your_service_role_key
```

**⚠️ ВАЖНО:** Смените пароль на более надёжный!

Рекомендуемый пароль должен содержать:
- Минимум 16 символов
- Заглавные и строчные буквы
- Цифры
- Специальные символы
- Без словарных слов

Пример хорошего пароля: `K#9mP$xL2vN@qR8w`

### Шаг 3: Перезапустить сервер разработки

```bash
npm run dev
```

## 🔍 Как проверить работу

### Проверка Rate Limiting:

1. Откройте `/auth/login`
2. Введите неправильный пароль **5 раз**
3. Должна появиться блокировка на 30 минут
4. Кнопка "Войти" станет неактивной

### Проверка логирования:

1. После нескольких попыток входа откройте консоль сервера
2. Вы должны увидеть логи вида:
   ```
   ✅ [timestamp] Login SUCCESS: username="admin", ip="127.0.0.1"
   ❌ [timestamp] Login FAILED: username="admin", ip="127.0.0.1"
   🚫 [timestamp] Login BLOCKED: username="admin", ip="127.0.0.1"
   ```

### Проверка мониторинга:

1. Войдите в админ-панель с правильными данными
2. Перейдите на страницу `/admin/security`
3. Вы должны увидеть:
   - Статистику попыток входа
   - Таблицу с последними попытками
   - Информацию о настройках защиты

## 🎯 Что защищает эта система

### ✅ Защищено:

1. **Brute Force атаки** - rate limiting блокирует перебор паролей
2. **IP мониторинг** - все попытки записываются с IP адресом
3. **XSS атаки** - httpOnly cookie недоступна из JavaScript
4. **Частично CSRF** - sameSite: "lax" cookie

### ⚠️ Что можно улучшить:

1. **2FA (двухфакторная аутентификация)** - добавить Google Authenticator
2. **IP Whitelist** - разрешить доступ только с определённых IP
3. **JWT токены** - вместо простых cookie
4. **NextAuth или Supabase Auth** - профессиональная система аутентификации
5. **Email уведомления** - при подозрительной активности
6. **CAPTCHA** - после нескольких неудачных попыток

## 📝 Логи безопасности

Все попытки входа записываются в:
1. **Консоль сервера** - в реальном времени
2. **Supabase таблица** `admin_login_attempts` - постоянное хранение

Структура лога:
```typescript
{
  username: string,
  ip_address: string,
  user_agent: string,
  status: 'success' | 'failed' | 'blocked',
  reason: string | null,
  attempted_at: timestamp
}
```

## ⚙️ Настройка параметров

Для изменения параметров rate limiting, отредактируйте:

**Файл:** `src/lib/rate-limiter.ts`

```typescript
export const loginRateLimiter = new RateLimiter(
    5,              // maxAttempts - максимум попыток
    15 * 60 * 1000, // windowMs - окно в миллисекундах (15 минут)
    30 * 60 * 1000  // blockDurationMs - длительность блокировки (30 минут)
);
```
